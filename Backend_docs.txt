3. Why Use 2 Backends Instead of 1?
Reason 1: Node.js is built for I/O; Python is built for Math
Node.js uses an asynchronous, single-threaded event loop. It is blazing fast for I/O operations (handling simultaneous web requests, reading/writing to MongoDB, streaming PDFs). However, if Node executes heavy mathematical matrix equations or linear solvers, it blocks the event loop, freezing the server so no other user can even log in!
Python is the global standard for Scientific Computing, Operations Research, and Math. Libraries like scipy.optimize and HiGHS are compiled directly in C++ and solve complex optimization matrices in single-digit milliseconds.
Reason 2: The "Greedy Starvation" Problem Requires Operations Research

A simple JavaScript backend typically assigns volunteers using a greedy loop (whichever task is checked first gets the volunteer). As seen earlier:

If Volunteer A has both Crowd Control and rare Medical Triage, a greedy loop might assign them to Crowd Control, leaving the emergency triage station with 0 doctors (a shortage).
Python’s Mixed-Integer Linear Programming (MILP) solves all locations and tasks simultaneously as a global system of linear equations, finding the mathematically optimal distribution.
Reason 3: Independent Scalability
95% of user interactions are reading profiles, editing requirements, or downloading sheets. Node handles that lightweight traffic effortlessly.
Heavy optimization only runs when someone clicks "Generate Deployment Plan". Because it lives in an isolated microservice, it can be scaled independently on dedicated compute instances without affecting web traffic.
Reason 4: Zero-Downtime Resilience (Graceful Fallback)

If the Python engine is temporarily offline (e.g., during updates or container restarts):

The Node backend does NOT crash.
Node automatically catches the offline status and falls back to its built-in local heuristic matching.
Coordinators can still generate plans and do their work without any downtime.
Reason 5: Industry Standard Architecture for Major Projects

Real-world systems that solve logistics and scheduling (such as Uber dispatching drivers, FedEx routing packages, or airline crew scheduling) never run optimization algorithms inside their primary web backend. They separate the Web/API Gateway from the Optimization/Dispatch Engine. Using this design demonstrates advanced microservice architecture and operations research in your major project.
